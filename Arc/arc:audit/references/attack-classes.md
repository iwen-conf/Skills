# AppSec Attack Classes

Read in [appsec.md](appsec.md) Phase 3. Select classes by the trust boundaries in the Phase 1 asset
table, never by a language or dependency name alone. Adapted from
[cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill) at `c1c8a8c`
under the [MIT license](upstream/security-audit-LICENSE).

## 1. Ordinary classes (every appsec run)

| Class | Check |
|---|---|
| Injection | entry → sink for SQL/NoSQL, shell, template, file path, redirect, deserialization, LDAP, log; second-order use (stored safely, used raw elsewhere); injection through field names, keys, headers and metadata, not only values |
| Access control | the right permission on the right object through the right mechanism: a parallel path to the same state change with a weaker check; body fields overriding scope (`owner_id`, `tenant_id`, `role`); authentication without authorization; bulk, batch, export and import without per-item checks |
| Resource and files | traversal through symlinks, encoding and null bytes; SSRF through redirects, DNS rebinding and URL-parser differences; unsafe deserialization; archive extraction outside the target; temp files; check-then-use races |
| Crypto and secrets | weak randomness for tokens and nonces; secrets in source, logs, errors, URLs or client responses; missing MAC verification, nonce reuse, non-constant-time comparison, ECB or static IVs; failure paths that fall back to no crypto |
| Business logic | skipped, reversed or replayed steps; partial failure without rollback; check-then-act races (double spend, double approval); negative, zero, overflow, precision and string/number coercion; stored or upstream data trusted because "it was validated on the way in"; expiry boundaries and clock skew; posture when config, a flag or a dependency is missing |
| Feature abuse and leakage | export or backup above the caller's level; import or restore bypassing validation or ownership; search, filter or sort as an oracle for hidden data; enumeration through error text, status, size or timing (login, reset, invite); preview or draft tokens with broad scope; user-set webhook or callback URLs fetched by the server |
| Chained and second-order | what component A guarantees versus what B assumes (truncation, coercion, normalization, tenant scope); a stored value reused as path, URL, regex, template or policy; token, key, plugin or agent capability growing after refresh, delegation, caching or role change; setup, migration, revoke and cache-expiry windows; undo, restore and rollback that skip current ownership |
| Obvious exposures | committed secrets and key files; security TODO/FIXME; debug mode reachable by env, query or header; seed or default credentials; unauthenticated `/debug` `/admin` `/metrics` `/env` `/config`; `.gitignore` gaps; unpinned dependencies; dynamic eval/exec; credentialed wildcard CORS; flags on sensitive cookies; open redirects; stack traces in production errors. Check each item literally, then trace the path before reporting |
| Wildcard | the strangest, half-finished or compatibility code; API calls the UI never makes; undocumented routes, parameters and headers; feature combinations (preview + cache, import + webhook, OAuth + impersonation); reverted security fixes in history; account actions that affect other users or operator spend; what the tests never exercise |

## 2. Domain classes (select when the boundary exists)

| Domain | Select when present | Classes | Confirm only with |
|---|---|---|---|
| HTTP and identity | proxies, gateways, custom parsers, sessions, CSRF, JWT, OAuth/OIDC, SAML, MFA, passkeys, recovery, API keys, mTLS | request desync; cache poisoning by unkeyed input; private responses cached; Host/Forwarded trust; header injection; CSRF; session fixation and logout invalidation; cookie scope; JWT signature and `iss`/`aud`/`exp`/`alg` binding; OAuth `state`, `redirect_uri`, PKCE and callback binding; SAML signed-object binding; MFA downgrade and step-up bypass; account-linking collisions; reset and recovery tokens; API-key scope; mTLS peer versus application identity | two components reading the same request or token differently, or an invalid credential accepted |
| Client and browser | SPAs, extensions, webviews, service workers, browser storage, `postMessage`, CORS, WebSockets | DOM XSS; DOM clobbering; prototype pollution; `postMessage` origin and source checks; cross-site WebSocket use; credentialed CORS; service-worker scope and cache identity; tokens left in storage after logout; XS-leaks; clickjacking on sensitive actions; client navigation to attacker URLs | a source → sink path in shipped client code with a cross-origin or cross-user effect |
| Data isolation and lifecycle | multi-tenant stores, caches, search, analytics, export, backup, migration, deletion, retention, restore | missing tenant or owner filter; composite-key collisions; policy versus query disagreement; signed URLs reaching too far; search, cache and index ACL drift; logs and analytics as alternate readers; aggregate oracles; export and restore scope; migration defaults; soft-delete bypass; stale authorization on derived copies; retention overrun; restore reviving invalid state | two dummy tenants through the same local path |
| Supply chain and CI | dependency resolution, codegen, CI workflows, release, signing, updates, plugins | namespace confusion; mutable inputs (tags, fetched scripts); generated-source provenance; secrets in the build context; untrusted PR code in privileged workflows (`pull_request_target`, self-hosted runners); expression injection in workflow commands; cache and artifact trust mixing; over-scoped automation tokens; build-to-release substitution; unsigned updates and rollback; plugin trust expansion | the workflow or manifest line and the privilege an untrusted input reaches |
| Cloud and deployment | IAM, IaC, containers, Kubernetes, mesh, serverless, edge, ingress, provider events | workload identity overreach; cross-account role trust; application authorization delegated to cloud metadata; reachable management plane; trusted-proxy or mesh identity bypass; metadata endpoint reachability; privileged containers and host mounts; admission policy gaps; secrets shared across workloads; credential-renewal fallback; bucket and signed-URL policy; event-source identity | configuration rendered from the repository |
| Protocols, RPC, messaging | gRPC, GraphQL, Protobuf/Thrift, custom protocols, queues, pub/sub, webhooks, streaming | framing and canonicalization disagreement; enum and default confusion; envelope versus payload identity; interceptor coverage per method; peer identity mapped to an application principal; per-item authorization in streams and batches; reply correlation; topic and subscription scope; dead-letter disclosure; untrusted producer as control plane; duplicate and out-of-order delivery; acknowledgment before commit; partial multi-consumer transitions | the handler path and a message a lower-trust producer can send |
| Resource exhaustion | untrusted work consuming shared CPU, memory, disk, connections, workers, queues, quotas or paid spend | superlinear regex or parsing; decompression amplification; query amplification (N+1, unbounded page size); unbounded buffers and cardinality; leaked handles; work continuing after cancellation; heavy pre-auth work; quota scope and reset gaps; pool starvation; reachable panic or deadlock; retry storms and fail-open; poison records blocking a queue | a bounded local measurement of the growth; never load a shared or live system |
| Desktop, mobile, local IPC | native apps, deep links, webview bridges, exported components, helpers, local daemons, sockets, XPC, Binder, D-Bus | deep-link ambiguity and account handoff; intent and file-open authority; navigation into a native bridge; over-broad bridge capabilities; webview file access; IPC peer authentication; claimed versus channel identity; exported activities, services and providers; privileged helper as confused deputy; install and update path trust; local file TOCTOU; credential-store mismatch; account switch and restore leakage | the manifest or bridge registration and a call a lower-trust app or page can make |
| Memory safety and binaries | C/C++, unsafe Rust, FFI, parsers, decoders, loaders, JIT, kernel interfaces | out-of-bounds access; integer overflow and truncation; unit or pointer-depth confusion; uninitialized data; use-after-free; type confusion; ownership races, TOCTOU, lock order; pointer-length contracts across FFI; layout and enum mismatch; unwinding across FFI; library search-order trust; malformed binary metadata; repeated user-copy reads | a sanitizer or harness result; a crash alone is not code execution |
| AI, LLM, agents | RAG, memory, tool calling, MCP servers or clients, prompt assembly, model-controlled actions | indirect injection from retrieved content; cross-session or cross-tenant context bleed; memory poisoning; role and provenance confusion; tool-argument injection into sinks; excessive agency and confused deputy; approval not bound to the final action; schema versus dispatcher disagreement; unbounded action loops; sub-agent and MCP trust inheritance; MCP tool identity and metadata used as policy; unsafe output rendering; sensitive context extraction | a concrete tool call or disclosure that attacker-controlled content causes, and whose authority it uses |

## 3. Domain discipline

- A missing header, cookie flag, MFA prompt or rate limit is not a finding by itself; require an
  accepted invalid request, cross-principal impact, assurance downgrade or credential disclosure.
- Name both sides of every disagreement (proxy and application, policy and query, schema and
  dispatcher) and the exact value each side sees.
- Tenant and lifecycle claims list every copy of the record: primary, cache, index, event, export,
  backup, deleted and restored.
- A decisive fact held by a proxy, identity provider, cloud account, browser or deployed config that
  the repository does not show is `manual-gap` with the missing fact and the owner's check.
