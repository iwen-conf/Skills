# Markdown 接口契约

新增、修改或编写项目接口文档时读取本文件。前后端围绕同一份可评审的 Markdown 契约实现和验收。

## 文档格式与归属

1. 接口说明使用 `.md`，放在项目已有 API 文档目录；无既有约定时使用 `docs/02-API记录/`，以 `README.md` 索引模块或接口文档。
2. 用标题、字段表、行为表和验收清单表达契约。禁止用 `.json`、OpenAPI JSON、JSON Schema 或整段 JSON 代码块代替接口说明；嵌套字段用字段路径和父子说明，样例值写在表格中。
3. 仓库内 Markdown 是接口契约基准，开发、联调和验收均以它为准。默认不调用 `apifox-cli`，不要求创建 Apifox 项目、登录、同步或导出。只有用户明确要求平台同步时才使用 Apifox，且它只是文档的下游副本；已有 Apifox 项目也不构成自动同步的理由。旧平台定义与文档不一致时先核对实现和需求、更新 Markdown，再按需同步，不能让平台记录覆盖文档基准。
4. 这是文档格式约束；接口实际传输编码、已有机器生成文件及工具输入输出仍遵循项目协议，不因文档改用 Markdown 而改动运行时行为。
5. 先通过 `arc-idx` 找到当前路由、DTO、调用端、错误定义和测试，再编写契约。领域字段、角色和枚举必须引用项目合同、代码或用户需求中的真实定义；未知项标为待确认并阻塞依赖该项的实现。
6. 复用已有模块文档或接口章节，避免为同一接口新增重复说明。实现前写清预期行为，变更时同步文档、调用端和受影响任务，交付时补充验证证据。

## 契约最小内容

| 内容 | 必须写清 |
| --- | --- |
| 接口定位 | 业务目的、需求来源、方法与路径、调用端、后端实现位置 |
| 权限边界 | 认证方式、允许的角色/权限、资源归属检查；全部来自项目定义 |
| 请求字段 | path/query/header/body 位置、字段路径、类型、必填、可空、默认值、约束与示例值 |
| 响应字段 | 字段路径、类型、必有、可空、含义、单位/时间格式、枚举来源与示例值 |
| 行为与状态 | 正常、空数据、参数错误、未认证、无权限、资源不存在、业务冲突及系统失败的实际语义 |
| 业务规则 | 校验与状态变化；有写入时说明副作用、事务边界、幂等或并发约束；列表说明分页/排序/筛选 |
| 兼容与依赖 | 受影响调用端、契约变更点、前置依赖、关联前端/后端任务 |
| 验证 | 场景、命令或操作、预期结果、实际证据与验证环境 |

按接口实际情况填写；不适用的能力写明原因，不为填表虚构分页、幂等键、角色、错误码或接口版本。

## Markdown 模板

下列内容是模板，交付前替换提示项。每个接口使用独立章节；复杂接口可独立成文件，由模块索引链接。

```markdown
# 模块接口

## 契约依据

- 需求/设计：链接到当前文档及章节。
- 当前实现与调用点：已检索确认的路径、符号。
- 契约状态：草案 / 已对齐 / 已验证；写明依据，文档已写不等于接口已实现。
- 关联任务：后端任务链接、前端任务链接；仅单端时注明实际范围。

## 接口名称

### 基本信息

| 项目 | 约定 |
| --- | --- |
| 业务目的 | 调用后完成什么行为 |
| 方法与路径 | 项目已确认的方法、路径 |
| 认证与权限 | 认证要求、权限来源、资源归属规则 |
| 调用端 | 页面、客户端或服务调用点 |

### 请求字段

| 位置 | 字段路径 | 类型 | 必填 | 可空 | 默认值 | 约束/含义 | 示例值 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 按实际填写 | 项目字段 | 项目类型 | 是/否 | 是/否 | 无或实际值 | 边界、单位、枚举来源 | 脱敏值 |

### 响应字段

| 字段路径 | 类型 | 必有 | 可空 | 含义与约束 | 示例值 |
| --- | --- | --- | --- | --- | --- |
| 项目字段 | 项目类型 | 是/否 | 是/否 | 单位、时间格式、枚举来源 | 脱敏值 |

### 行为与错误

| 场景 | HTTP 状态/业务结果码 | 返回语义 | 调用端行为 |
| --- | --- | --- | --- |
| 正常 | 按项目合同填写 | 业务结果 | 对应成功状态 |
| 无数据（适用时） | 成功状态 | 空集合及约定分页信息 | 展示空态 |
| 参数不合法 | 按项目合同填写 | 字段错误与原因 | 展示可纠正提示 |
| 未认证/无权限 | 分别填写 | 区分身份与权限失败 | 按项目约定处理 |
| 资源不存在/业务冲突 | 分别填写 | 明确业务语义 | 按项目约定处理 |
| 系统失败 | 按项目合同填写 | 类型化错误与可追踪信息 | 展示错误态 |

### 业务规则与兼容性

- 校验、状态变化、分页/排序/筛选：按实际填写。
- 写入副作用、事务、幂等与并发：按实际填写，不适用则说明原因。
- 变更点及受影响调用端：写明是否需要同步修改，链接对应任务。

### 验证场景

| 场景 | 前置条件与输入 | 命令/操作 | 预期结果 | 验证证据 |
| --- | --- | --- | --- | --- |
| 本接口的具体行为 | 真实条件、脱敏字段值 | 项目命令或操作步骤 | 可观察结果 | 待验证或证据链接 |
```

## 与任务拆分联动

- 契约对齐是依赖该契约的实现任务的前置条件；契约变更较大时独立建任务，简单改动可包含在后端任务中。
- 前端与后端任务必须各自链接同一份 Markdown 契约的具体章节，并写明依赖的字段、行为及就绪条件。不能仅写“等后端完成”或“联调一下”。
- 前端可以依据已对齐契约先做页面、状态与 Mock 验证；需要真实接口验收的任务，在只验证 Mock 时保持待验证。后端接口通过不能代替前端任务验收。
- 公共响应、错误语义或鉴权约定变化时，列出实际受影响的接口与调用端并同步各自任务；不能只更新一个示例端点。
