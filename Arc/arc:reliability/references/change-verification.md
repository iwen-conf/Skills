# 本次变更验证卡

需要书面交付时把下面字段合入已有 PR、测试说明或任务卡；不必另建文档。稳定规则链接到当前合同，不复制领域规格。不适用字段删去，未知写缺口；示意 ID 不能代替项目领域标识。

## 变更与合同

- 变更/候选版本、目标环境、范围与允许的操作：
- 受影响规则及来源、调用者/共享状态、适用维度：
- 失败后果、暴露/发现/恢复依据、项目风险优先级：
- 业务预期、禁止结果、规格缺口：
- 正常/故障/恢复/升级的适用范围；明确不测或暂缓的内容、理由与残余风险：

## 必需场景与执行

| 场景 / 规则来源 / 本次必需 | 条件 / 交错 / 故障与恢复 | EXPECTED / FORBIDDEN | 独立 Oracle | 要发现的缺陷 / 反例检查 | 实际选择器或步骤 / 真实边界 |
|---|---|---|---|---|---|

规格和绑定在上表维护；每次实际运行的结果放到下面证据表。没有实际观察不能先填 PASS。

关键断言的反例检查按风险选择，不能把编译失败/环境失败算成抓到业务缺陷。对生成式测试写明数据分布、状态/历史与已知盲区。设计示例见 [`worked-example.md`](worked-example.md)。

## 当前证据

| 场景 | 候选 / 配置 / 环境 | 运行 / 工具 / seed 或 schedule | 实际观察与制品 | 状态 / 缺口 |
|---|---|---|---|---|

允许状态：`PASS / FAIL / BLOCKED / NOT_RUN / FLAKY`。必需观察器失败、证据过期或错误环境不能据此通过；重跑保留先前尝试。

记录候选与实际交付配置的差异，及其对主张的影响；模拟、替代依赖或历史基线的证据不能扩张为真实运行结论。隔离测试须注明丢失的主张、负责人和修复条件，必需主张仍未通过。

## 门禁与闭环

- 必需证据缺失/失败、原项目门禁结果：
- 检测、停止、回滚/前滚、补偿/恢复及负责人（适用时）：
- 风险接受记录（若项目已有授权决定，独立保留原测试状态）：
- `arc:test` / `arc:fix` / `arc:sdlc` 后续及完成条件：

大型或跨会话任务按 `arc:sdlc` 拆分和同步进度，写明先跑的精确 `<Context-Queries>`；普通验证卡不创建任务树。
