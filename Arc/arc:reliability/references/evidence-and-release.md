# 环境、证据与发布门禁

用于可靠性验证的环境准备、运行记录和候选版本判定。复用项目现有工具与 CI，不要求引入统一 runner。

## 环境契约

运行前从真实配置确认目标版本/提交、服务与依赖版本、数据命名空间、账号权限、测试入口以及允许的操作。数据库名、topic、bucket、测试租户都来自项目事实。

环境代表性按主张判断：数据库隔离级别、驱动/消息确认语义、旧新版本共存、数据量/分布、配置与后台作业可能决定结论。记录测试环境与目标面的差异及其影响；不要求复制整套生产基础设施，也不能省掉正在验证的关键条件。

| 生命周期 | 确认内容 |
|---|---|
| Prepare / bootstrap | 复用什么已授权的环境和客户端；哪些资源归本次运行所有 |
| Reset / fixtures | 只重置本次拥有的测试数据；测试独立环境与测试同步环境不混用 |
| Healthcheck / observe | 应用、依赖、断言观察器就绪；观测权限和时钟/版本足够解释结果 |
| Run / isolation | 不消费生产 topic、不参与生产 leader election、不把通知/支付发到真实目标 |
| Teardown / evidence | 失败/超时也释放本次资源；保存失败与清理失败，不能删除他人数据或吞错 |

工具顺序：现有 runner/fixtures/CI → 平台原生能力 → 有具体失败模型需要的最小新工具。工具安装不得顺带改变默认运行时或拉起服务端。测试工具本身的单元检查应保持 hermetic；真实数据库/容器连接属于明确的集成验证。

本机默认只装/用客户端。容器操作绑定用户指定的远程 Docker context/SSH，确认目标 daemon 后执行；不要把项目 Testcontainers 当成本机容器许可。PostgreSQL 只用远端已有实例/CI，禁止安装/初始化/启动本机服务端。`psql`/`libpq`/`usql` 等客户端不能顺带安装服务端 formula；SQL 交互按项目约定使用 `usql`。SSH tunnel 绑定 `127.0.0.1`，不向公网暴露数据库。

准备数据库/缓存/队列/索引/对象存储测试配置时使用 `.xxxx.json` 隐藏文件，区分独立测试与同步测试用途；优先引用现有 secret/env 机制，不把凭据写入报告。未知目标不得猜默认 DSN，授权不足也不得通过自建本机数据库绕过。

共享/第三方目标的负载、故障注入及破坏性 reset 必须在既有明确授权范围内。核对目标、操作、数据所有权、爆炸半径、停止和恢复措施；授权已覆盖则继续，不重复确认。缺少必要信息时保留问题，并继续能独立完成的规则/绑定/本地检查。

## 一份可信运行证据

使用现有 CI 报告或项目格式。下列信息是语义要求，不是新建 JSON schema 的指令。

| 关联 | 记录 |
|---|---|
| Claim / scenario | 对应规则、场景 ID、EXPECTED/FORBIDDEN、是否本次必需 |
| Candidate / surface | 提交或构建身份、未提交改动指纹（若有）、场景/配置版本、环境与真实依赖版本 |
| Execution | 真实工作目录、命令/测试选择器、工具版本、开始/结束/耗时、退出结果 |
| Reproduction | 测试数据身份、seed、调度/barrier、corpus 或失败输入、重现步骤（适用时） |
| Observation | 实际业务终态、断言、必需观察器状态、日志/历史/对账制品与证据状态 |

保存脱敏日志；命令里的 DSN、token、账号密钥用变量名代替。记录足以重放的非敏感配置/数据版本，不把“脱敏”变成无法关联运行的理由。

证据必须属于当前候选版本和适用环境。旧提交、旧配置、不同迁移阶段的绿灯不自动沿用；有明确适用性证明才复用，否则相关场景待运行。`SKILL.md`、计划、CI YAML 或测试文件存在只表示准备工作。

覆盖插桩、sanitizer、模拟时间或替代依赖可能改变运行行为。按风险确认实际交付构建/配置的证据，不把插桩覆盖率或模拟吞吐当成发布版本的真实性能。

## 事实状态

| 状态 | 含义 |
|---|---|
| `PASS` | 实际执行，必需观察器有效，业务断言成立，证据可关联本次候选 |
| `FAIL` | 实际执行违反合同/断言；区分产品失败与 runner/observer/teardown 失败，后者不证明产品错误 |
| `BLOCKED` | 具体前置条件不可用，无法执行或完成可信判定；写明缺什么及已完成的独立工作 |
| `NOT_RUN` | 本轮未执行，例如被裁剪、跳过或证据过期待重跑；写明原因 |
| `FLAKY` | 同一条件结果不稳定、原因未确认；保留所有尝试与历史，不能重跑到绿就抹掉失败 |

规格缺口 `SPECIFICATION GAP` 是规则/判定尚未定义，不是测试通过状态。运行期间的观察器失败需要单独记录；受影响场景无法判定则 `BLOCKED`，验证器本身可记 `FAIL`，门禁仍不通过。

## 不稳定测试与对照诊断

保留首次失败及全部重跑，记录候选、测试/工具版本、环境和数据差异。可用同条件的已知基线或 placebo 运行帮助判断失败来自候选、环境还是测试；对照结果只是诊断证据，不能自动推翻业务断言或把共同缺陷判成通过。

隔离 flaky 只能改变调度和处置方式：记明负责人、原因、修复条件和失去的主张覆盖。被隔离的必需场景仍是 `FLAKY/NOT_RUN`，门禁继续阻断；需要稳定的替代证据、修复后的有效运行，或独立记录的授权风险决定。风险决定不改变测试事实状态。

已确认判定器/fixtures 存在错误，可以修正后重新取证；保存修正依据与新测试版本。禁止改期望去迁就产品缺陷。修复后新的有效运行可记 `PASS`，旧失败不能从历史消失。

## 门禁判定顺序

1. 从变更影响与业务后果确定**本次必需场景集合**，复用稳定场景。集合不能因结果失败临时删减；需要调整时给出合同/范围变化依据。
2. 每个场景关联规则、执行模式与可信 oracle。自动化有可运行绑定；人工有步骤和实际观察；分析有假设、模型和结论。需要真实运行语义的主张不能用分析文件替代。
3. 验证每份证据的候选身份、环境、结果、观察器与制品可用性；损坏、重复冲突、缺字段/断言的证据是缺口，不静默跳过或取最后一个 PASS。
4. 必需项逐项满足约定且原项目门禁通过，才给出“已满足本次可靠性门禁”。必需项 `FAIL/BLOCKED/NOT_RUN/FLAKY` 均阻断；低风险测试数量、覆盖率或总分不能抵消。
5. 记录残余风险及必要的检测/停止/回滚/恢复条件。项目已有风险接受流程时单独记录决策者、范围、到期日和补偿控制，保留原失败状态；Agent 不自批豁免，不把有豁免写成“测试通过”。资金、数据、权限不变量不能用可用性错误预算豁免。

门禁给出决策输入，不执行上线、远程重启、回滚或修改发布开关。若用户已要求这些操作，转入相应实现/运维流程，携带当前证据与原有授权，不额外制造批准步骤。

## 成本与执行节奏

| 周期 | 合理范围 |
|---|---|
| 本地 / PR | 改动规则的确定性案例、关键真实依赖集成、必要静态/race 检查与本次必需场景 |
| 主干 / 定时 | 较宽的并发矩阵、fuzz、兼容、故障注入、负载/soak 切片（按风险启用） |
| 候选发布 | 本次完整必需集合，适用的迁移、恢复、回滚与端到端场景 |
| 生产 | 经授权的分阶段发布、SLI/业务不变量监测、对账与遏制，见 [`operations-and-learning.md`](operations-and-learning.md) |

达到本次约定证据后结束；仅在新改动、失败或未解决风险出现时扩大/重复测试。不要把昂贵验证全部塞进每次 PR。

按依赖图/历史 trace 选择测试时，补查动态配置、新入口和共享不变量；未出现在历史 trace 中不代表没有影响。选择依据不足时扩大到相关合同回归，不能默默省略关键场景。
