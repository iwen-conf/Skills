## 统一模型 v2

`schema_version: 2`；`id` 为不可覆盖的图版本，`system` 是稳定系统节点 ID，`previous` 可关联上一版本。节点、规则、不变量、测试都使用稳定 ID；执行 task ID 加图版本前缀，同一测试的多次运行另有 run/round。

| 对象 | 契约 |
| --- | --- |
| Nodes | system/domain/capability/boundary/role/data/contract/deployment，以及 action/condition/state；名称、说明、来源、能力输入/输出 |
| Rules | 现有 action/actor/entry/oracle/conditions/expected/rejected/source，增加来源引用与要求引用；文档来源仍需明确批准 |
| Invariants | 范围、Oracle、观察边界、对独立测量的可执行比较；不从动作响应推导预期 |
| Tests | 条件赋值、Rule/动作、预期、拒绝策略、验证对象、测试依赖、参与账号角色和 fixture 恢复要求；定义与运行分开 |
| Constraints | 明确来源的条件逻辑子句；用于有界可达性求解，不自动创造业务规则 |
| Flows | 能力、初始状态和业务流转；正常、拒绝、重试、补偿和并发关系显式描述 |

关系的合法端点在 Go 校验器定义，导入拒绝未知字段、重复 ID/JSON 键、错误端点和非法树结构。

| 关系 | 用途与约束 |
| --- | --- |
| contains | system→domain→capability 及同类拆分；能力归属单父、无环；不充当执行顺序 |
| implements | capability→action；同一能力可跨多个入口和行为 |
| depends_on | 能力或边界依赖；影响分析走反向依赖，循环给出诊断 |
| owns / uses_contract / serves / collaborates_with | 边界所有权、跨边界契约、角色与领域协作；共享所有权需显式理由 |
| requires / forbids / transitions / recovers / next | 保留既有规则/行为语义，不能混成能力树 |
| transitions_to | 状态→状态，附动作、Rule/条件赋值、结果分支；流程探索只消费此类业务关系 |
| verifies | 测试→规则、能力、行为分支、不变量；用于义务与覆盖 |
| test_depends_on | 测试执行前提；单独拓扑检查，不能由 contains/depends_on 暗示执行顺序 |

旧格式（省略版本或 v1）继续按旧约束解释，不重新命名旧任务或 RAW。新规范完整体保存在追加的模型表；原 nodes/edges/rules 保留当前列形与语义。v2 hash 纳入规范完整体，v1 hash 算法保持不变。`init` 幂等追加表/索引，事务失败不留下半升级状态；回退保留旧账本，新记录不可由旧二进制错误放行。

## 义务、可达性与点亮

默认规则义务继续有 POSITIVE、逐条件 NEGATIVE/FORCED。v2 加上已声明流转、不变量、显式边界/并发/幂等/恢复测试；缺场景仍形成待绑定义务或缺口，不能因为没创建任务而消失。测试依赖只决定本轮调度。

条件约束求解有状态数、步数和时间上限。完整求解得出的不可达组合保留约束 ID、图版本和证明范围，单独列为模型排除；不标成运行 PASS。未知或截断不能排除义务。可执行任务仍需独立确认实际前提，模型可达不证明 fixture 已满足。

同一次验收固定 graph、environment、target、candidate/config/fixture/runner hash 和 logical round。选择历史轮次可查看原判定，但必须显示当前有效性。不同环境/轮次的局部 PASS 不拼成全套通过。

后端提供完整义务分母和四维覆盖：能力、行为、分支、不变量。节点状态为 PASS/PARTIAL/FAIL/NOT_RUN/BLOCKED/STALE/FLAKY，并携带文字原因。PASS 要求完整适用义务全部有当前有效 RAW；真正反例才是 FAIL；未满足 graph gate 不等于业务缺陷。旧 FAIL 计数与首个偏离始终保留。

变更分析比较稳定 ID 与合同内容，再分阶段传播：条件/规则/数据/契约→所影响动作/边界→能力→反向能力依赖→验证测试。不混入无关流转边。缺测试能力、所有权冲突、依赖环、无恢复等诊断带对象 ID 和来源。

## 执行与恢复

新增有界 `execute`；执行规格为 JSON，声明真实动作适配器、独立 Oracle、参与账号别名、fixture、单步与总时限、并发上限、恢复动作及输入文件 hash。支持标准 HTTP 与已有 CLI（浏览器/设备/数据库）argv；不从 UI 接收任意 shell 命令。环境和凭证继续引用现有配置与 fixture registry，凭证不进入模型/RAW/网页。

动作前读取真实条件/主体，执行后由独立 Oracle 读取状态与不变量测量。记录实际 node/transition/input/expected/observed/verdict/RAW；拒绝必须有拒绝观察与前后读回，不能用响应成功码或 fixture 声明代替业务成功。并发和跨角色记录所有参与主体绑定。

外部副作用恢复独立于动作事务：执行声明的隔离恢复协议、保存操作记录、独立读回目标状态/测量，确认安全才释放 fixture。失败保留原 FAIL，不能改为 PASS；超时终止进程组并记录截止，后续复用须通过恢复 checkpoint。有限模型求解、工具自测、真实 API/浏览器/设备分别报告范围。

## 补齐的义务、报告与探索（BG19–BG24）

| 能力 | 设计合同 |
| --- | --- |
| EXISTENCE | `tests[]` 中 `kind: EXISTENCE` 绑定一条规则（每条规则最多一条）；义务是"当前候选上有独立实现证据"。只认该规则动作最新的 `scan`：PRESENT 且证据 hash 未变、带 `commit` 且等于所选 round 的候选提交才 PASS；NOT_FOUND 只生成候选缺口（BLOCKED），扩大检索并经用户确认后才记 MISSING；不接 runner |
| SEQUENCE | `kind: SEQUENCE` 声明 `flow` 与 `steps`（从 flow 初始状态起首尾相接的 transition 边），`rule` 为末步规则；runner 每步一个批次、顺序一致，每步按自身 transition 的规则取 Oracle 与条件；作为一个义务整体执行，第一个偏离步即首个偏离，之后不再执行；每一步的规则都要已批准 |
| CONSISTENCY | `kind: CONSISTENCY` 声明 `layers`（`ui`/`api`/`database`/`async` 中 2–4 层，各带独立 Oracle ID）；runner 末步必须挂上每层 Oracle；各层读回一致才通过，任一层不一致 FAIL，缺观察为 BLOCKED |
| 风险报告 | `risks` 表增加状态（OPEN / ACCEPTED_RISK / PROMOTED）、范围、决策原话与证据引用；`report --kind acceptance|risk` 分别输出；验收 gate 不计风险数；项目配置 `risk_review` 打开时才另设风险审查门禁 |
| 状态等价 | 等价键 `EK = (flow, 状态, 角色, 主体别名, 相关条件取值, 声明的历史属性取值)`；相关条件 = 从该状态在 flow 内可达的 transition 前置条件/guard 里出现的条件，按约束子句闭包。历史属性由 v2 可选字段 `history[]` 声明（`id`、`flow`、`set_by`/`cleared_by`/`enables` 为 flow 内 transition——`enables` 列出只在该属性为真时才允许的 transition，`measurement` 供运行时读取，来源须为 user/document）；模型探索沿路径计算，运行时从 oracle measurement 读。`exploreFlow` 的键是"状态 + 本 flow 声明的历史属性"（模型探索中条件每步独立求可满足，不进路径状态）；同键再次到达不展开，记入 `merges[]`，所有叶子都被合并时 `paths` 可以为空。只在 `EK` 全等且每个分量都有观察时合并；缺观察记 `EQUIVALENCE_UNDECIDED` 不合并。运行时键再加上 runner 声明的全部 measurement，除非模型 `equivalence.ignore` 带来源排除；未声明的差异不合并并生成 `UNDECLARED_DIFFERENCE` 风险候选。合并记录 `{key, kept, merged, basis, scope}` 随探索结果输出并受同一预算约束。探索（W02）、派生义务（W08）、DISCOVERY（W09）共用；依据与原型见 `.arc/artifacts/verify-route-alignment/research/state-equivalence.md`（W10 定稿） |
| 连续执行 | `run-chain` 按已知路径（已规划、READY、恰有一个当前有效 runner，按依赖排序）逐卡调用同一 `execute`，每步仍写 RAW、独立判定；遇到偏离、未知状态、前提不满足、新分支或预算耗尽就停，退出码 10–15 分别对应，0 为完成；一张卡都跑不了时以 blocked 停。上下文包只含当前状态、偏离步（RAW 路径与 hash）、从该状态出发的已声明转移、未执行的卡和缺 runner 的卡 |
| 派生义务 | `derive --run --budget` 读 FAIL 运行首个偏离步的独立读数：观察状态是已知状态时，对每条从它出发、规则已批准的转移派生"该转移义务须从等价状态再验证"（RULE 来源，进分母；本轮里起点等价键相同的合格 PASS 才满足）；观察状态不在模型里时只记推断探索项（`report --kind risk` 的 `derived_risks`）。按运行时等价键去重、每个来源运行有上限并标 `truncated`、按风险分排序；原 run、首个偏离和冻结任务不变 |
| DISCOVERY | `discover record` 登记探索观察（证据、入口、主体、前后状态），按模型判出 `UNDECLARED_ACTION/STATE/TRANSITION/DIFFERENCE` 四类 UNSPECIFIED；不判 PASS/FAIL、不进分母；等价键去重、每次有上限。`discover triage` 在真实终端由用户分流：遗漏需求交 arc-plan（新图版本）、不应存在进风险报告、允许扩展记理由排除 |

## 来源分离、反证与自测（BG26–BG31）

| 能力 | 设计合同 |
| --- | --- |
| 来源类别 | 规则来源 `user`/`document`（需批准才是 RULE）；实现证据来自 `scan` 与执行观察，单独存放，不进入规则表；RISK 增加 `origin`：`ai_inference`、`industry_practice`、`peer_reference`（附参照条目 ID） |
| 三向比对 | `report --kind risk` 增加三栏：要求有而实现无（EXISTENCE 候选缺口）、实现有而要求无（UNSPECIFIED）、参照有而要求无（RISK 候选）；每条带来源与证据引用 |
| 反证记录 | `risk refute --result supported|refuted|not_found --evidence` 登记一次反证（追加表 `risk_refutations`，证据 SHA-256 绑定）；风险报告每条显示最新结果、证据与历史，没登记过为 `not_attempted`，证据改过为 `evidence_changed`；`refuted` 的风险仍是 OPEN，由用户决定关闭 |
| 参照库 | 项目本地 JSONC 参照库（`.arc/verify/references/*.jsonc`）。条目含 `id`、`domain`、`invariant`、`slots`（1–8 个，节点种类 + 小写提示词）、`relations`（槽位间必须存在的边）、`trust`（`project_document`/`public_spec`/`user_design_document`/`project_code`）、`source`/`source_ref`；缺来源拒绝导入。匹配求槽位绑定：恰好一个 → `origin=peer_reference` 的 RISK，`reference=<条目ID>@<文件SHA前12位>`；找不到 → `NO_BINDING` 并写明槽位（不叫"不适用"，提示词会漏同义词）；多个 → 一条 `AMBIGUOUS` 诊断。模型可选 `reference_bindings` 显式绑定或标不适用（带来源）；已有 `covers` 覆盖、W21 台账驳回过、同引用同绑定已存在的都抑制；单次最多 50 条。只进风险报告，不进验收 gate、不变 RULE（W19 定稿，实现 W24） |
| 检出率 | `mutation-report`：读取注入清单（缺陷类别、注入位置、预期应失败的义务 ID）与对应运行结果，输出检出/漏检；注入与部署由已授权 runner 完成，CLI 不改被测源码 |
| 分流精度 | `reject-risk`（交互）补上"驳回"决定：图风险写 REJECTED 事件，参照风险记入 `reference_rejections` 并在之后同绑定匹配时抑制；风险报告 `triage_summary` 按来源类别汇总接受/驳回/待定与样本量，少于 10 标样本不足；不进门禁、不算质量分 |

## 静态快照

`arc-verify snapshot --graph <id> [--env <alias>] [--round <id>] [--run <id>[,<id>...]] --assets <workbench 构建目录> [--out <目录>]` 运行一次即退出。上下文只取账本里实际存在的 v2 版本、环境、轮次和运行；不存在就报错，不猜默认值。未知命令（含已删除的 `workbench`）在打开账本前就报错。

| 产物 | 内容 |
| --- | --- |
| `snapshot.json` | `meta`（生成时间 UTC、CLI 版本、导出命令 argv、图版本 hash、环境、轮次）、catalog、版本化模型与批准状态、六种视图投影（含完整义务分母、诊断、`truncated`）、分析与四维覆盖、与 `previous` 版本的差异和待复验测试、所选运行的 trace、首个偏离和脱敏 StepRAW |
| `index.html` + 构建资源 | 复制 `--assets` 的构建产物；同一份 JSON 以 `<script type="application/json" id="arc-snapshot">` 内嵌，`file://` 打开不需要网络请求 |

- 导出时逐条重验 RAW 的 SHA-256、身份和引擎捕获，脱敏后写入；校验失败的证据作为失败条目写出（阶段、run、step、原因），不省略也不当成通过。凭证、密钥和任意本地文件内容不进快照。
- `--out` 必须不存在或为空目录，不覆盖旧快照；默认放在 `.arc/verify/snapshots/<graph>/<UTC 时间>/`，和账本一样不提交。总大小超过上限就失败，并报出超限的部分，不静默截断证据。
- 页面是时间点视图：显著显示生成时间与上下文；不发网络请求（CSP `default-src 'none'`，脚本、样式只取同目录资源）；没有执行、批准、导入、重试入口。
- 快照 JSON 沿用原接口的命名 DTO（视图、trace、evidence），由 Go 定义；`workbench/src/types.ts` 与 Go DTO 的 JSON 字段由一项 Go 测试比对，不一致即失败；前端不自行计算 PASS。开发用 `vp dev` 读取由 CLI 导出的样例快照 `tools/arc-verify/workbench/dev/sample-snapshot.json`（`TestSnapshotSampleForWorkbench` 从 v2 course 参考模型导出；`academic-v1` 是 v1，不能做多视图），不手写样例。构建产物里出现 `/api/` 时导出直接拒绝。

## 用户流程与验收

### 六视图的职责与导航合同

2026-10-31 用户再次确认 Multi-View Business Graph：六视图消费同一业务模型，各自按关系类型投影；三个工作空间只是入口分组，不保存独立业务副本。下表为需求合同，不表示当前界面已经验收。

| 视图 | 展示与结构 | 下钻与计算边界 |
| --- | --- | --- |
| 系统业务全景 | 领域、服务角色、核心场景与业务协作拓扑 | 点击领域进入能力地图；入口不展开 API 清单 |
| 业务能力 | 领域与能力的分层树或能力矩阵 | contains 构树；角色、能力状态与覆盖可过滤；流程内校验行为不自动升级为对外能力 |
| 业务边界 | 责任容器、规则/数据/能力所有权、对外契约和跨边界调用 | 显式共享附理由；重复所有权、职责重复候选和依赖环可定位；部署节点单独展示，不以进程推定业务归属 |
| 业务流程 | 行为有向图与状态机 | 正常、拒绝、回退、重试、补偿、并发及状态转移显式呈现；不拿 contains 或测试依赖计算业务路径 |
| 测试验证 | 关联测试、必需义务与证据驱动的节点状态 | 版本/环境/轮次固定后计算；节点可进入场景、实际运行、首个偏离与 RAW；颜色同时提供文字含义 |
| 业务影响 | 明确依赖关系与变更传播图 | 展示传播依据和待复验测试；所有权、归属、流转边不无差别参与依赖遍历 |

跨视图选择使用稳定实体 ID，并保留图版本、环境与轮次。目标视图没有该实体时，说明其不适用原因，允许返回原选择；不得创建同名替身。课程/报名等示例只有显式概念模型标识，缺少真实执行证据时不可点亮为 PASS。

能力完整度分别呈现“已描述、已实现、已验证、已上线”的证据与缺口，不合并成完成布尔值：已描述关联模型和来源；已实现关联当前候选的实现证据；已验证使用当前完整义务及有效 RAW；已上线关联部署版本、环境和发布证据。缺发布证据时显示未知；上线不推出已验证。此处是展示合同，持久化字段与接口扩展须先由 W01/W04 明确，不让前端自行拼造。

覆盖缺口、所有权冲突、变更影响、完整度、历史质量与执行瓶颈均带实体 ID、上下文和来源。推测职责重复只记诊断候选；共享声明不免除规则验证。回放只播放所选真实 run 的顺序与并发记录，提供输入、观察结果和证据；缺步骤或并发顺序未知时如实显示，不补造线性路径。

打开快照即固定导出时的图版本/环境/轮次。建模空间看全景、能力、边界、流程；验证空间看义务、运行结果与回放；分析空间看覆盖、缺口、完整度、边界耦合与影响。编辑候选、规划和执行在 CLI 完成，再重新导出快照。选择能力保留 ID，能继续进入流程和关联测试/RAW。空模型、快照缺失或损坏、证据校验失败、无执行/缺绑定都显示可理解的状态。

前端使用文本和颜色双重表达，所有导航/树展开/选择/回放支持键盘和可见焦点，尊重 reduced motion。超出投影上限显示截断；原生表格仍可查看义务与证据。UI 不合成业务通过状态。
