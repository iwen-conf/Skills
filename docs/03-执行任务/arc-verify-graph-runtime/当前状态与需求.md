# ARC Verify：当前状态与需求

> **跨 Grok、Codex、Claude Code 等现有编程 Agent 的唯一交接方式：阅读并更新普通 Markdown。**
> 本文件不是 ACP、Agent 会话格式、模型配置、CLI 任务状态机或新的数据系统。适用于本仓库 ARC Verify 的现行工作范围。

## 一、已确认需求

1. **使用现有 Agent，不重造 Agent。** 当前 Grok/Codex/Claude Code 自行阅读业务、发现边界、设计/运行测试、修正假设；ARC Skill 约束过程和证据质量。
2. **不开发原生交接。** 不需要 ACP、跨 Agent RPC、Agent session/checkpoint、模型网关、交接 CLI、模型 URL、模型 API Key 或后台 AI 服务。切换 Agent 时直接阅读本文及已有目标项目文档。
3. **测试职责保持独立。** 现有 Go CLI/Turso/Graph v2/任务卡/独立 Oracle/RAW/可信门禁继续服务于测试执行、恢复和复验；已有 Campaign Checkpoint 不是 Agent 交接。
4. **业务完整性。** 系统 → 业务能力 → 业务边界 → 流程/动作/条件/状态的图谱与可视化；已确认 RULE 与发现的 RISK/UNSPECIFIED 分开，未经人工确认不得将 AI 假设升级规则。
5. **安全真实性。** 真实业务验证需要明确目标授权、独立 Oracle、身份一致性和原始证据；未知副作用不得直接重放，模拟结果不得冒充真实 E2E。
6. **工作记录要具体。** 每个任务写清需求来源、预期结果、完成状态、代码基线、实际运行证据、阻塞、风险和后续动作；切换 Agent 无需恢复之前的聊天上下文。

## 三、切换 Agent 后的操作（文档方式）

1. 阅读本文件、目标项目的需求/设计/任务文档与 `Arc/arc:verify/SKILL.md`。
2. 校验 `main` HEAD、相关业务代码、Graph 与规则状态、环境授权；旧文档可能过期。
3. 选择一个**未完成任务**，查证现有测试、首次 FAIL、Oracle、RAW 和历史结论；不要重新发起有未知副作用的操作。
4. 使用当前 Agent 已有的代码阅读、终端与测试工具，按 Skill 约束完成该任务；不需要任何模型配置或 Agent 间特殊操作。
5. 结束前更新下表/工作记录，写明下一位 Agent 可以直接实施的下一步。

## 五、每次任务记录模板

### YYYY-MM-DD / 任务 ID

- **需求/来源与确认程度：** 已确认 RULE / 用户明确需求 / AI 提出的待确认假设。
- **范围与验收：** 系统/业务能力/边界、角色、前置条件、允许/禁止行为。
- **代码和环境：** Git commit、Graph/Rule、fixture、Oracle、测试目标授权。
- **完成情况：** 已实施 / 进行中 / BLOCKED / NOT_RUN / VERIFIED（必须有可信证据）。
- **实际操作与结果：** 修改文件、测试命令及 exit code、RAW/Oracle 路径、首次偏离。
- **未完成/风险：** 仍需确认的规则、没有覆盖的路径、禁止重放的副作用。
- **下一步：** 具体到文件、命令、测试和可观察的成功条件。

只记录已发生、可复核的事实。不要以历史聊天记录、未运行的测试或 scripted AI 输出代替实际验证。
